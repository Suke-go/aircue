# AirCue 0.6.0

Windows向けTauriアプリです。v0.6はかんたん音響編集と実験セットを追加します。

## 起動

起動中の旧版を閉じ、同じフォルダーの `AirCue.exe` を起動します。タイトルに「AirCue 0.6.0」と表示される版がこのソースのビルドです。WebView2 Runtimeが必要です。現在のWindows環境で動作確認しています。

## 使い方

上部の「波形作成」「オーディオ」「タイムライン」「実験」「出力設定」で、同じウィンドウ内の画面を切り替えます。編集途中の波形、クリップの選択、配置・補正値を保持します。実験操作は専用画面へ分け、刺激編集の画面には表示しません。

1. 「波形作成」の「標準波形」から選ぶか、部品を追加し、押し出し・戻り、正弦波、三角波、丸めパルスを編集します。
2. 下部の「配置位置」と「出力レベル」を調整します。1波形の上限は80 msです。
3. 「波形を保存」で波形一覧に登録します。標準波形を編集した場合は別の波形として保存し、自分で保存した波形を編集した場合は更新します。
4. 「タイムライン」を開き、波形一覧から左右のトラックへドラッグします。「左へ／右へ」と「配置」ボタンでも追加できます。
5. クリップを選択すると開始位置・レベル補正を変更できます。レベル補正は−60〜＋24 dB、0.5 dB刻みです。元の波形レベルと補正の合計を表示します。ドラッグで位置とトラックを移動できます。
6. 「出力設定」で機器を選択します。2ch表示の機器も選べます。プレビュー先もここで設定します。各画面の再生ボタンから実際に再生します。

## v0.6の追加

- Audioは「かんたん」が既定。リング、ドラッグできる音源点、8プリセット、距離・強さで編集し、「詳細」で従来の経路編集へ入ります。切替だけでは経路を変更しません。
- A 原音／B 立体音響を、保存設定を変更せず比較できます。
- 「実験」で4テンプレートとJSON因子表から匿名参加者ごとの試行順を生成し、manifestと完成WAVのExperiment Bundleを保存できます。
- Unityで校正確認後に試行し、予定時刻・開始観測・回答・中止理由を記録します。最初の版の基準刺激は音声1クリップ＋空気刺激1クリップです。

具体的な研究手順、4〜8反復の初期案と制約は [実験セットと初期実験案](docs/EXPERIMENT_DESIGN.md) を参照してください。

## オーディオ

「音声を読み込む」でWAV、MP3、FLAC、OGG Vorbis、M4A（AAC/ALAC）、AIFFを取り込みます。1ファイル128 MB・10分まで、1プロジェクト64素材までです。読み込んだ音声は48 kHzステレオへ変換し、`data/assets` にコピーするため、元ファイルを移動しても使えます。モノラルは左右共通、3ch以上の素材は先頭2chを使用します。

素材の開始位置と再生時間を指定して切り出します。1クリップ20 ms〜60秒、タイムライン全体は最大60秒です。音声レベルは−60〜＋12 dB、タイムラインのレベル補正は−60〜＋24 dBです。ピーク超過時は再生・書き出しを拒否します。

「立体音響」をオフにすると元の左右を保持します。オンにするとモノラル化し、MIT KEMARのHRTFでイヤホン用に定位させます。平面図で方位・距離を動かし、仰角はスライダーで調整します。固定・周回・指定位置までの移動・通過点を使った経路編集を選べます。非個人化HRTFのため、前後・高さの感じ方には個人差があります。距離は1 mを超えた分の音量減衰のみで、室内反射や近距離HRTFはモデル化していません。

定位プリセットは正面・右・後方・左・周回・左→正面→右・頭上を通過・正面から接近の8種類です。経路では開始・通過点・終了を図から選んでドラッグし、高さや時刻を調整できます。「経路の確認」で任意時刻の位置を確認できます（音声シークではありません）。再生時間を変更すると通過時刻も比例して変わります。高さのグラフをドラッグすると、通過時刻と仰角を同時に調整できます。「左右反転」「逆順」「等間隔」「終点を始点に合わせる」で経路をまとめて変更できます。「取り消す／やり直す」はオーディオの編集に対応します（最大40段階、アプリ終了で履歴を破棄）。

正弦波・三角波・矩形波・ホワイトノイズ・周波数スイープも生成できます。プレビュー中の変更は再レンダリング完了後に短いクロスフェードで反映します。長いクリップでは反映に時間がかかるため、実験は数秒程度から始められます。繰り返し再生にも対応しています。

詳細仕様は [立体音響の設計](docs/SPATIAL_AUDIO.md) を参照してください。

「タイムラインに配置」でオーディオトラックへ追加し、空気砲の左右トラックと合わせられます。再生対象は「すべて」「オーディオのみ」「空気砲のみ」から選べます。4chを開けない機器では対象を切り替えて試聴します。

クリップの「音源・位置を編集」から経路を開き直し、「クリップを更新」で反映します。「複製」で音源・経路・補正を保持した別クリップを作れます。立体音響をオフにしても経路設定は保持します。

音声を含む `.aircue` プロジェクトを保存すると、同じ場所に同名の `.media` フォルダーも作成します。別のPCへ渡す場合は両方を一緒にコピーしてください。

## Unityへの取り込み

1. タイムラインの「Unityへ書き出し」で保存先フォルダーを選びます。
2. 作成されたフォルダー内の `AirCueUnity` をUnityの `Assets` へコピーします。
3. `Sequence.aircueseq` をシーンへドラッグし、Playします。

音源の定位・経路・レベルをWAVに反映済みなので、追加のSpatializerは不要です。初期状態はイヤホン用ステレオ再生です。4ch同時出力用のWAVと左右の空気砲WAV、開始時刻・経路の情報も同梱します。Unity 6で取り込み・Prefab生成を検証済みです。実機の4ch再生にはUnityのQuad出力と端子対応の確認が必要です。AirCueのASIO機器設定はUnityへ引き継がれません。

詳しい操作と出力条件は [Unity連携](unity/README.md)、設計は [UNITY_INTEGRATION.md](docs/UNITY_INTEGRATION.md) を参照してください。

## 実験との同期

「実験連携」でローカル接続を開始し、現在のタイムラインを準備します。Unity側の`AirCueExperimentClient`へ画面のポートとセッショントークンを設定すると、試行ID付きで`status`、`prepare`、`play`、`stop`を送れます。

連携は同じPCの`127.0.0.1`だけで待ち受けます。試行開始時にレンダリングせず、`prepare`で固定した4chバッファを50〜5000 ms先へ予約します。編集後は準備済みデータを自動的に破棄します。記録は`data/experiment-events.jsonl`へ追記します。

`started`は音声コールバックが予約位置を通過した観測であり、耳や空気砲出口での物理刺激開始ではありません。精密な実験ではマイク、圧力・光センサー、DAQなどによる遅延測定が必要です。プロトコルとログの定義は [実験同期設計](docs/EXPERIMENT_SYNC.md) を参照してください。

## 標準波形

12種類を用意しています。すべて80 ms以内、初期出力レベルは−18 dBです。タイムラインの波形一覧にも表示されます。既存プロジェクトでは不足分だけを追加し、既存の波形・クリップ・設定を上書きしません。

| 波形 | 内容 | 長さ |
|---|---|---|
| 単発パルス | 押し出し12 ms・戻り48 ms | 60 ms |
| 丸めパルス | sin²パルス | 20 ms |
| 三角波 40 Hz | 2周期 | 50 ms |
| 正弦波 40 Hz | 2周期 | 50 ms |
| 短い押し出し | 押し出し6 ms・戻り24 ms | 30 ms |
| 長い押し出し | 押し出し16 ms・戻り64 ms | 80 ms |
| 速い押し出し | 押し出し4 ms・戻り56 ms | 60 ms |
| 押し出し・戻り同幅 | 押し出し20 ms・戻り20 ms | 40 ms |
| 短い丸めパルス | sin²パルス | 8 ms |
| 長い丸めパルス | sin²パルス | 40 ms |
| 正弦波 30 Hz | 2周期 | 約66.7 ms |
| 正弦波 60 Hz | 3周期 | 50 ms |

標準波形は駆動波形の初期値です。空気砲での体感に合わせてプレビューしながら調整してください。

## 保存と書き出し

編集内容は実行ファイルと同じフォルダーの `data/project.json` に自動保存されます。直前の保存は `project.backup.json` に残ります。このフォルダーへの書き込み権限が必要です。

「タイムライン」の「保存／開く」で `.aircue` プロジェクトを保存・読み込みできます。読み込んだ後は出力機器を選び直してください。

WAVは48 kHz・24 bit PCMです。波形作成からはモノラル、タイムラインからは設定に従った4chを書き出します。オーディオ画面からはステレオを書き出し、タイムラインではイヤホン音声と空気砲をそれぞれの割り当てへ書き出します。

## 出力

- ASIO / WASAPIを列挙し、チャンネル数や48 kHzへの対応状況だけでは選択を禁止しません。4chを優先し、再生できなければ他の対応形式を試します。サンプルレートは機器に合わせて変換します。
- 初期割り当てはイヤホン左1ch・右2ch、空気砲左3ch・右4chです。4用途を自由に入れ替えできます。
- 2chとして開いた機器では、再生対象の左・右の信号を選択機器のL/Rに送ります。1chでは左右を半分ずつ合成します。再生に使った形式を画面下部に表示します。
- 互換再生でのL/Rは選択したWindows/ASIO出力の左右です。Rubix44本体のどの端子へ出るかは、選択した出力とドライバーの設定によります。
- 2ch機器を別々に束ねる機能はありません。イヤホンと空気砲の4ch同時出力には4chとして開ける出力が必要です。WAV書き出しは従来通り4ch・48 kHzを維持します。
- 出力レベルはデジタルゲインです。dB SPL、風速、知覚強度への換算ではありません。
- 空気砲の距離は左右各30 cm、出口径は20 mmを初期値とします。距離による自動補正は未実装です。
- 初期波形は−18 dB。合成ピークが0 dBFSを超える場合は再生・WAV書き出しを止めます。自動正規化は行いません。
- 押し出し・戻りは、それぞれsin²形状です。戻りの振幅を時間比で調整して波形の積分を釣り合わせています。実機の振動板変位や噴流量を保証するモデルではありません。

## 今回の範囲

波形生成、部品合成、80 ms編集、波形一覧、左右タイムライン、保存／読み込み、WAV書き出し、4chルーティング、実音声プレビュー、音声取り込み、HRTF定位・経路編集、音声と空気砲の統合タイムライン、Unityからのローカル試行制御とJSONL記録。

Unityへの完成音響の書き出し・取り込みを実装しています。実測データの取り込み、音圧／流体モデルと校正、頭部追跡に応じた動的レンダリングは今後の実装です。ND90-8・A07を接続した空気砲での体感・出力確認は未実施です。

## 開発

Rust、Visual Studio C++ Build Tools、WebView2 Runtimeが必要です。フロントエンドは同梱のHTML/CSS/JavaScriptを使用し、Nodeのバンドル工程はありません。

通常ビルド:

```powershell
cargo test
cargo build --release
```

ASIO対応ビルドには公式ASIO SDKとlibclangが必要です。

```powershell
$env:CPAL_ASIO_DIR = 'C:\path\to\ASIOSDK'
$env:LIBCLANG_PATH = 'C:\path\to\libclang-directory'
cargo test --features asio
cargo build --release --features asio
```

公式SDK取得先: https://download.steinberg.net/sdk_downloads/ASIO-SDK_2.3.4_2025-10-15.zip

`AirCue.exe --diagnostics diagnostics.json` で、音を出さずに機器の列挙結果をJSONへ保存します。テスト用データの保存先は環境変数 `AIRCUE_DATA_DIR` で変更できます。

ASIO SDKにはSteinberg独自ライセンス／GPLv3の選択肢があります。SDKの通知を `THIRD_PARTY_ASIO.txt` に同梱しています。この構成ではGPL v3の選択肢を使用し、配布時には対応ソースを同梱します。リポジトリは非公開です。

## GitHubでのビルド・配布

非公開リポジトリ: https://github.com/Suke-go/aircue

- `main` へのpush、Pull Request、手動実行で、Windows x64のテストとTauriビルドを実行します。
- 成果物はActionsの `AirCue-windows-x64` から14日間取得できます。
- `v0.5.0` のようなタグをpushすると、テストとビルドの成功後にGitHub Releaseへ自動配布します。
- ReleaseにはNSISインストーラー、ポータブルZIP、対応ソース、SHA-256を添付します。非公開リポジトリへのアクセスが必要です。
- 個人アクセストークンの登録は不要です。Releaseジョブだけに `contents: write` を付与し、GitHubの組み込みトークンを使います。

バージョンを上げる場合は `Cargo.toml`、`package.json`、`tauri.conf.json`（ウィンドウのタイトルを含む）を更新し、`npm install --package-lock-only` と `cargo check` でlockfileを更新します。`npm run check` が一致を確認します。mainへpushしてCI成功を確認した後、対応するタグをpushします。

```powershell
git tag v0.5.1
git push origin v0.5.1
```

コード署名とアプリ内の自動更新は未設定です。新しい版はReleaseから取得して更新します。署名なしのためWindowsが発行元確認を表示することがあります。

## ソースから再ビルド

CIはRust 1.95.0、Node.js 24、Windows 2022 runnerを使用します。ローカルでは `npm ci`、`./tools/setup-asio.ps1`、`npm run tauri -- build --bundles nsis --features asio -- --locked` で同じ構成をビルドできます。

Releaseの `source.tar.gz` にはCargo依存ソースとASIO SDKも含まれます。展開後に `CPAL_ASIO_DIR` を同梱 `ASIOSDK` へ、`LIBCLANG_PATH` をlibclangの場所へ設定すれば、`cargo build --release --locked --offline --features asio` で実行ファイルを再生成できます。MSVC Build ToolsとWindows SDKは別途必要です。

AirCueのコードはGPL-3.0-only、MIT KEMARデータは著作者の条件に従います。ASIO SDKはGPL v3の選択肢を使用します。通知は `LICENSE`、`NOTICE.txt`、`THIRD_PARTY_*.txt` を参照してください。非公開設定でも、成果物の受領者には対応ソースを提供します。
